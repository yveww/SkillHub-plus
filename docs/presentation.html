The Problem · 痛点
同一个 Skill，
不同 Agent 调用，效果天差地别。
用户无处反馈，开发者无从知晓。

企业自建 Skill 在市场发布后，在不同 Agent 环境、不同使用场景下效果差异巨大。但缺乏类似 GitHub 的 Issue 反馈机制——问题在用户端沉默积累，开发者无法及时感知和修复，最终侵蚀 Skill 质量与用户信任。

核心矛盾Skill 开发者无法获知用户端真实问题，用户也无法有效反馈

03 / Core Mechanism

AI 兼容性诊断四步法

从 Skill 端出发，多环境横测 + 归因定位 + 适配建议，排查效率提升 10 倍

01 · Reproduce
问题复现
在用户报告的环境中模拟相同 Prompt 重新运行，记录执行日志和异常堆栈，确认可复现性
02 · Compatibility Test
多环境兼容性横测
在 Trae / Doubao / 飞书机器人 / 用户 aily 等多个环境下跑同一个 Skill 用例，生成兼容性矩阵，快速缩小排查范围
03 · Adaptation
适配定位
分析 SKILL.md 和参考文档，定位需要适配的代码段（如缺少某平台工具调用格式、条件分支未覆盖、上下文处理不足）
04 · Attribution
归因判定
综合横测结果和定位分析，输出归因分类和适配建议：Skill Bug / 平台兼容 / 配置问题 / 上下文问题 / 使用问题
